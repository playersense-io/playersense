# Changelog

All notable changes to the PlayerSense Unity package.

## [0.1.0] — unreleased

First package. Analytics, identity, consent and context over the shared Rust core.

### Added

- Errors, exceptions and crashes, off until `Logs.Enabled` is set: Unity's log, unhandled and
  unobserved-task exceptions on any thread, Android exit reasons (11+) and iOS MetricKit (14+)
  read on the next launch, and an abnormal-exit marker where neither exists. No signal handler.
  `PlayerSense.Logs` for errors, caught exceptions and breadcrumbs, and `BeforeSend`.
- A separate answer for error reports: `Privacy.GrantErrorReports`, `DenyErrorReports`,
  `ErrorReportsFollowAnalytics`, `PendingCrashReports` and `DiscardPendingCrashReports`.
- `ChildDirected`, which sends no player id and no attributes with an error report.
- A thread of the SDK's own for recording logs and ticking the core, so no SDK work that takes
  time runs in a frame; `SDK.MainThreadCost` and the diagnostics window show what is left on
  the main thread. Performance tests for the capture callback, a storm of errors, and garbage
  per captured line.
- `PrivacyInfo.xcprivacy`, and the answers for App Privacy and Data safety in the README.
- `PlayerSense.Analytics.Track` and `TrackRevenue`.
- `PlayerSense.Identity.SetPlayer` / `ClearPlayer`, and the installation identifier.
- `PlayerSense.Privacy.Grant` / `Deny` / `SetConsent`, with pre-consent events held in memory
  and never written to disk.
- `PlayerSense.Context.Session` and `PlayerSense.Context.Player`, a generic key/value
  vocabulary that decorates events without being copied onto each one.
- Project Settings integration, so a game with a project key needs no integration code.
- **Window ▸ Analysis ▸ PlayerSense**, showing what the SDK has actually done.
- Four play-mode tests covering the C#/native seam, and `verify.sh`, which runs them in a
  throwaway Unity project — in the editor, in real Android and iOS player builds, and on an
  attached phone under IL2CPP.
- Native plugin import settings applied from the folder on load, rather than trusted to a
  `.meta` file generated by whichever machine built the binaries.
- `[assembly: AlwaysLinkAssembly]`, so IL2CPP managed stripping cannot delete this assembly.
  Without it a build with stripping at High removed it outright, which would have made the
  zero-code integration — a project key in Project Settings and no `Track` call anywhere —
  silently collect nothing.

### Changed

- `Track` no longer reports success for an event the player declined. The core returns one of
  queued, held-for-consent or declined, which reach C as `PS_OK`, `PS_HELD_FOR_CONSENT` and
  `PS_DECLINED_BY_CONSENT`. Check the **sign** of a status, never equality with `PS_OK`.
- A malformed event name is now rejected whatever the player has consented to. It used to
  return success to a declining client, so a misspelled name was invisible until production.
- The diagnostics window's consent counter was labelled "Held for consent" and counts the
  opposite — events *discarded* because the player declined. Relabelled.

### Not included yet

- `PlayerSense.Flags`, `PlayerSense.LiveOps` and `PlayerSense.Log`. The server side of these
  does not exist, and an API that always returns the fallback is worse than no API: a studio
  would ship targeting rules that never match and have nothing to tell them why.
- WebGL.
- Generated typed events.
